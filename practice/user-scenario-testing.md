## 문제

로봇 배달 서비스는 로봇과 웹 서비스가 함께 움직여야 완성됩니다. 그런데 Sanity Test는 기능 단위 체크리스트였습니다.

- 기능을 하나씩 통과해도 실제 이용 흐름에서는 문제가 났습니다.
- 로봇과 웹이 상태를 주고받는 구간의 결함은 릴리즈 뒤 CS로 들어오는 경우가 많았습니다.

## 한 일

- Sanity Test를 기능 목록 대신 사용자가 서비스를 이용하는 순서대로 다시 묶음
- 로봇 단독 기능뿐 아니라 웹과 주고받는 상태 변화까지 시나리오 안에서 확인하도록 설계
- 릴리즈 후 CS로 들어온 이슈와 QA가 찾은 이슈를 대조해, QA가 놓친 흐름을 시나리오에 추가
- 운영 사이트에서 자주 나오던 네트워크 불안정 상황을 별도 TC로 추가
- 기능 명세 단계에서 QA가 시나리오 관점으로 리뷰해, 명세와 TC가 어긋나는 부분을 개발 전에 정리
