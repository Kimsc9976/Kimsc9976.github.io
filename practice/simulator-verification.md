## 문제

배달 로봇이 다니는 인도와 횡단보도는 실기체로 같은 상황을 다시 만들기 어렵습니다. 보행자, 차량, 날씨가 매번 달라 현장에서 찾은 결함을 같은 조건으로 재현하기 힘들었고, 시험 한 번에 사람과 시간이 들었습니다.

시뮬레이터에 필요한 조건은 세 가지였습니다.

- 실제 도심 구조(연석, 경사로, 횡단보도, 건물 사이 GPS 음영)를 담은 시험장
- 자율주행 스택을 고치지 않고 그대로 붙이는 연결 방식 (실제 로봇 컴퓨터 포함)
- 별도 GPU 서버 없이 사내 PC 한 대에서 반복 실행할 수 있는 무게

## 한 일

### 1. 시뮬레이터 선정

후보 세 개를 위 조건으로 비교했습니다. 그래픽 품질보다 반복 실행 비용과 스택 연결 비용을 우선했습니다.

| 후보 | 확인한 것 | 결론 |
| --- | --- | --- |
| SimWorld (Unreal Engine) | 실기체와 같은 다중 카메라를 달면 FPS가 한 자릿수로 떨어짐. 카메라마다 렌더 결과를 동기식으로 복사하는 구조가 원인이라 설정으로는 풀리지 않음 | 재현 조건과 함께 오픈소스 이슈로 보고하고 제외 |
| URBAN-SIM (Isaac Sim) | 대규모 병렬 학습을 전제로 한 학습 인프라. 사내 장비로는 구동 단계에서 막힘 | 보류 |
| mvsim | 가볍고 ROS 2를 공식 지원. 대신 월드를 XML로 직접 써야 하고 토픽 이름이 고정됨 | 채택. 약점 두 가지는 도구를 만들어 해결 (2·3번) |

### 2. 맵 빌더: 좌표를 넣으면 도심 월드 생성

월드를 XML로 손으로 쓰면 맵이 커질수록 관리할 수 없게 됩니다. 지도 데이터에서 월드를 자동으로 만드는 빌더를 만들었습니다.

- 공개 지도(OpenStreetMap)와 공간정보를 합쳐 차도, 인도, 연석, 횡단보도, 보행 신호등, 건물, 지형 고저 생성
- 로봇 경로가 턱을 넘는 지점마다 경사로 자동 배치
- 위성 궤도를 계산해 건물에 가려 위치를 놓치는 구역을 등급으로 표시
- 위성지도에 겹쳐 실측하며 위치 정합 보정
- 결과: 서울 도심 여러 권역을 수작업 3D 모델링 없이 생성

### 3. 브릿지: 자율주행 스택을 코드 수정 없이 연결

- 시뮬레이터와 로봇 스택 사이에서 토픽을 중계하는 브릿지 개발. 스택은 실기체와 같은 코드로 동작
- 시뮬레이터 하나에서 여러 로봇 동시 운용: 실제 로봇 컴퓨터를 붙인 HILS, 별도 컴퓨터의 SILS, 연습·환경 세팅용 시뮬 전용
- 외부망이 막힌 사내 PC에서도 설치·구동되도록 구성

### 4. 성능 최적화

넓은 권역, 다중 로봇, 로봇마다 여러 센서라는 실제 시험 조건을 시뮬레이터가 버티지 못했습니다. 시뮬레이터 본체와 렌더 라이브러리(MRPT)를 직접 고쳤습니다.

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 넓은 권역 주행 | 지나온 구역 메모리가 쌓여 강제 종료 | 떠난 구역 메모리 자동 회수 |
| 그래픽 메모리 (다중 로봇) | 다중 로봇 주행 시 한계 | 사용량을 줄여 여유 확보 |
| 걷는 보행자 | 불가 | 다수 보행자에서도 센서 주기 유지 |
| 차량 | 없음 | 로봇 주변 차로 주행 |
| 센서 주기 | 목표 미달 | 다중 로봇·다중 센서에서 목표 주기 유지 |

### 5. 관리자 페이지: 시험 조건을 실행 중에 변경

시험 조건은 맵을 만들 때만 배치할 수 있었습니다. 실행 중에 바꾸는 웹 관리자 페이지를 만들었습니다.

- 로봇별 보행자·차량 밀도 설정, 이동 경로 직접 지정
- 볼라드, 점자블록, 벤치, 차단봉, 배수로 격자 같은 시설물 배치
- 차도와 횡단보도를 그 자리에서 그리기
- GPS 음영 구역을 등급별로 켜거나 직접 그리기

TC의 사전 조건을 맵 재빌드 없이 바로 깔 수 있게 됐습니다.

### 6. 검증 연동: 실행부터 판정까지 자동

- 직접 만들어 쓰던 검증도구를 새 시뮬레이터에 연결해 시나리오 로드 → 주행 → 결과 수집 → 판정 → 리포트를 자동 반복
- 건널목 TC 재설계: 상황을 축(경로 구성, 접근 방향, 형상, 노면 표식, 신호, 사람·물체, 시스템 상태, 환경)으로 정의하고, 장면 축은 현실에 있는 값 쌍을 pairwise로 빠짐없이 덮도록 TC 추가
- 건널목 단계(접근 → 정차 → 대기 → 횡단 → 진출)마다 관찰 가능한 Pass 기준을 정해 판정 기준 통일
- 같은 절차를 Local Path Planning 검증에도 적용
- 결과: 건널목 시험에서 실기체 전에 자율주행 결함을 찾아 등록

### 7. 문서와 운영 규칙

- 셋업 → 맵 작업 → 시험 → 종료를 처음부터 따라 하는 가이드, 사용 가이드, 구조·변경점 문서 작성
- 시뮬레이터 화면 촬영과 외부 공유 기준을 문서로 정리

## 남은 과제

- 주행 물리: 지금은 명령받은 속도를 그대로 따르는 단순 모델이라, 노면 마찰과 미끄러짐을 반영해야 합니다.
- 실내 주행: 엘리베이터 탑승과 층 이동은 아직 재현하지 못합니다.
- 동시 부하: 로봇마다 둘 수 있는 보행자·차량 수에 상한이 있어, 장비 증설 뒤 다시 측정할 예정입니다.
