## 문제

자율주행 로봇의 이슈는 그 순간 로봇이 무엇을 봤고 어떤 상태였는지를 알아야 원인을 좁힐 수 있습니다. 그 정보가 ROS 2 토픽의 원본 메시지와 숫자 코드로만 남아 있었습니다.

- 로그: 경로 계획 실패 코드, 횡단보도 주행 단계 같은 상태 값을 사람이 직접 해석해야 했고, 같은 로그를 부서마다 다르게 읽었습니다.
- 인지 결과: Semantic Segmentation·Object Detection 결과가 맞는지를 눈으로 판단해 사람마다 기준이 달랐고, 버전 간 비교는 수작업이었습니다.

## 한 일

### 1. NTT: 로그를 읽을 수 있는 상태로 (2024.12)

로봇에 연결해 토픽을 실시간 구독하고, 숫자 코드를 명세 기준 설명으로 바꿔 보여주는 데스크톱 도구입니다.

- 원격 관제 상태 등 운영 핵심 정보를 한 화면에 모은 시스템 모니터
- 경로 계획 실패 사유, 횡단보도 주행 단계를 코드 대신 설명으로 보여주는 상태 디버그 뷰
- 원격 접속으로 기체 설정 확인과 파라미터 변경. 현장 시험 준비 시간 단축
- 실시간 모니터링과 사후 분석을 같은 화면에서 처리하도록 설계해 부서 구분 없이 사용
- 로봇 SW 업데이트로 메시지 구조가 바뀔 때마다 도구를 함께 갱신

### 2. SS Tool: 인지 결과를 숫자로 검증 (2026.06 ~ 2026.10)

녹화 데이터나 실시간 토픽에서 카메라·인지 결과·3D 맵을 읽어, 브라우저에서 인지 품질을 정량 검증하는 웹 도구입니다.

- 카메라 영상, SS 결과, 3D 맵, 타임라인을 한 화면에서 동기화
- 검증 영역(ROI) 안 클래스별 점유율을 시계열로 표시
- SS와 3D 맵의 점유율 비교, 정답(GT) 대비 픽셀 일치율 계산
- 2D 검출 박스와 3D 객체 윤곽을 같은 클래스 색으로 그려 대응 관계를 바로 확인
- 버전 간 비교를 데이터 준비부터 이슈별 리포트까지 한 번에 실행. 중간에 멈추면 이어서 진행
- 인지 결과를 그 결과를 만든 버전의 클래스 정의로 판독. 정의가 없으면 해당 버전을 따로 빌드해 보관한 뒤 적용

## 판단 근거

- 지표 선택: SS와 GT를 클래스 분포로만 비교하면 좌우가 뒤바뀐 결과도 100%가 나옵니다. 픽셀 대응이 있는 GT에는 위치까지 보는 픽셀 일치율을, 픽셀 대응이 없는 3D 맵에는 분포 비교를 쓰도록 데이터마다 지표를 나눴습니다.
- 로직 제거: 2D 박스와 3D 윤곽을 공간 매칭하는 알고리즘을 먼저 만들었다가, 원본 트래킹 메시지에 이미 클래스 정보가 있다는 것을 확인하고 매칭 로직을 걷어냈습니다. 코드가 줄고 결과가 안정됐습니다.
- GT 점검: GT에도 오탐(건물 일부를 버스로, 오토바이 일부를 사람으로 표시)이 섞인 사례를 모아, GT를 정답으로 쓰기 전에 걸러야 할 항목으로 정리했습니다.
